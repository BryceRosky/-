# 第一轮技术审稿意见（多模态生成、离散扩散与强化学习方向）

## 审稿结论

**建议：大修后通过开题。** 选题有连续的前期成果，材料对 NFE 与真实时延、自反馈偏差、不同 checkpoint 不可横比等问题已有较好的自我约束。当前主要问题不是研究方向错误，而是核心概念尚未操作化、若干方法目标与实际优化量不完全一致、比较预算与统计协议不够具体。若不修改，答辩委员很容易质疑四项工作只是以“价值”为名串联、全掩码概率比并非真实重要性比率、部分状态自评分并不等于轨迹价值，以及第四项方案能否在可承受算力内完成。

以下意见只审技术、实验和可证伪性，不评价排版与参考文献真伪。

## 做得较好的部分

1. 报告没有把 NFE 下降直接写成端到端加速，并明确提出报告验证器、解码、显存和吞吐开销。这一点应保留。
2. 报告承认全掩码上下文是有偏代理、自反馈存在共享偏差、一步蒸馏可能损失质量，也把前三项已有结果与第四项拟开展研究分开，学术边界总体清楚。
3. 已提出固定预算与固定质量两种比较口径、独立理解基准、人工盲评和多随机种子，方向正确。
4. “生成秩不必然等于空间结构”“早期剪枝可能误删可恢复轨迹”“教师在学生异常状态上也可能不可靠”等判断准确，体现出对方法边界的认识。

## 必须修改的关键问题

### 1. “价值”尚未形成统一且可测的数学对象

报告反复使用“高价值 token”“高潜力轨迹”“条件补全价值”，但三个词目前分别由生成顺序、自验证分数和多次补全回报给出，可能是三个不同的代理量。委员可能会问：若早生成 token 因定义而被赋予高权重，再用采用该权重训练后的指标提升证明它“高价值”，结论是否循环？

建议在 **2.1 或 3.1** 增加统一定义，并明确训练效用与独立测试效用分开：

> 设与训练奖励相独立的终局效用为 \(U(x,c)\)，包含提示遵循、感知质量及必要的约束项；定义中间状态的条件补全价值为 \(V(z_t,c)=\mathbb E[U(X,c)\mid z_t,c,\pi]\)。轨迹筛选估计 \(V(z_t,c)\)，token 贡献用条件干预前后的价值差 \(\Delta_i=V(z_t,c)-V(\operatorname{mask}_i(z_t),c)\) 近似，结构学生则学习在固定预算下提高 \(V\)。训练时使用的奖励记为 \(R_{train}\)，所有机制结论最终以未参与训练和调参的 \(U_{eval}\) 验证。

这一段能把四项内容真正放进同一框架，也让“高价值”成为可证伪定义。需要补充说明：token 反事实替换可能产生分布外状态，因此采用条件重采样、同熵匹配或多次补全，并把结果称为“干预敏感度估计”，不要直接宣称严格因果效应。

### 2. 全掩码概率比不是真实行为策略的重要性比率

当前 **1.4、1.10、2.2（1）、3.2、4.1、6** 均使用“全掩码概率比/重要性比率”表述。rollout 中的动作是在真实部分可见状态 \(z_t\) 下采样，而分子分母均在 \(C_\varnothing\) 下评价时，

\[
\tilde r_i=\frac{p_\theta(z_i\mid C_\varnothing,c)}{p_{\theta_{old}}(z_i\mid C_\varnothing,c)}
\]

并不等于行为轨迹上的

\[
r_{t,i}=\frac{p_\theta(z_i\mid z_t,c)}{p_{\theta_{old}}(z_i\mid z_t,c)}.
\]

因此 PPO/GRPO 的重要性采样解释和裁剪信赖域解释不能直接沿用。全掩码做法可以作为有效的**提示条件代理比率**，但报告必须把术语改准。

精确改法：

- 将“概率比采用全掩码提示条件估计”改为“采用全掩码上下文定义提示条件代理比率，并以裁剪代理目标优化；该目标不作无偏 on-policy 策略梯度解释”。
- 第 3.2 节加入真实轨迹对照：在可承受子集上计算 \(r_{t,i}\)，报告 \(\log\tilde r_i\) 与 \(\log r_{t,i}\) 的 Pearson/Spearman 相关、符号一致率、裁剪率、KL 和最终性能；按生成阶段分别报告，不能只给总体相关。
- 用部分上下文估计作为中间点，形成“全掩码代理—部分上下文—真实轨迹”的偏差、方差、显存和时延曲线。
- 若论文仍沿用 importance ratio 这一原方法名称，应在首次出现处注明“原文称 importance ratio；从行为策略角度本文将其视为 surrogate ratio”。

### 3. 离散扩散中的“动作”和轨迹概率没有定义完整

一轮同时涉及 token 值预测、选择哪些位置固化、重掩码以及调度器。当前报告只讨论 token 类别概率，未说明掩码集合选择是否属于策略。若位置由置信度确定，而置信度又依赖模型参数，仅对 token 值做比率并不是完整轨迹策略。

建议在 **3.2** 明确定义：当前掩码集合 \(M_t\)、本轮新增可见位置 \(A_t\)、token 动作 \(a_t=\{(i,z_i):i\in A_t\}\)，以及调度器是固定环境规则、随机但不训练的规则，还是策略的一部分。若给定状态后各位置类别独立近似，可写

\[
\log \pi_\theta(a_t\mid z_t,c)=\sum_{i\in A_t}\log p_\theta(z_i\mid z_t,c),
\]

并说明当 \(A_t\) 的分布依赖 \(\theta\) 时忽略位置选择项会引入何种近似。比较方法必须使用同一掩码日程，或把日程差异作为单独消融，防止把 scheduler 收益归到信用分配。

### 4. 层次信用实验可能被“更多梯度/更大学习率”混淆

结构 token 权重 \(\lambda_s>1\)、结构阶段更多更新、不同覆盖率会同时改变总 token-gradient 数和有效步长。若不控制，HT-GRPO 的增益不能说明层次归因优于简单增加训练计算。

建议第 **3.2/3.6** 增加以下公平约束：

- 对每个 batch 将 token 权重归一化到 \(\frac1{|S|}\sum_i w_i=1\)，使加权前后平均梯度尺度一致。
- 所有信用基线匹配 rollout 数、优化器步数、累计参与反向的 token 数、训练 FLOPs、KL 目标和奖励调用次数。
- 增加“随机选择同样数量 token”“按熵但打乱生成秩”“只增加结构阶段更新但均匀权重”“同等总梯度范数”对照，排除额外计算和更大步长解释。
- 报告每阶段有效样本量、优势标准差接近零的 batch 比例、比率裁剪率和更新后 KL。奖励标准差过小时应跳过或降权，并在公式中加入 \(\epsilon\)。

当前“结合注意力/熵可视化判断早生成 token=结构”证据不足。注意力图只能解释相关性。建议以可量化检验为主：生成秩或结构分数预测 top-q 干预敏感 token 的 AUROC/AUPRC、与 \(\Delta_i\) 的 Spearman 相关，以及按计数、空间关系、属性和简单提示分层的置信区间；可视化只作辅助。

还应在 **1.4 或 1.9** 增加一句，避免看似矛盾：

> “早期阶段因可见上下文较少而具有较高的平均条件熵；同一早期状态内被优先固化的位置仍可能是相对高置信位置。本文区分跨阶段条件熵与阶段内选择置信度。”

### 5. HTS 的复杂度和 NFE 口径写得过度简化

**1.6** 将分层搜索概括为从 \(O(NT)\) 降到近似 \(O(N+T)\)。所引 dMLLM-TTS 自己给出的前向代价包含 \(N T_s\)、逐步宽度和、以及 \(K(T-T_r)\)；只有把 \(T_s,K\) 和衰减规则视为常数时才可作 \(O(N+T)\) 简写。否则容易被委员当场指出。

建议替换为：

> “线性搜索的主模型前向代价为 \(NT\) 个轨迹步；HTS 的代价为 \(N T_s+\sum_{t=T_s}^{T_r}W_t+K(T-T_r)\)，在论文采用的固定保留宽度和几何收缩设置下显著低于 \(NT\)。文中所称 \(O(N+T)\) 是特定固定参数下的渐近简写，实验将报告实际轨迹步数、FLOPs 与端到端时间。”

第 **3.3/3.6** 还需明确定义：CFG 条件/无条件两次计算如何计 NFE，融合 batch 是否仍按样本前向计数，不同模型规模如何折算，验证器调用是否计入等效 NFE。建议同时报告

\[
C_{gen}=\sum_t W_t,\qquad C_{verify}=\sum_{t\in\mathcal S}W_t c_v(t)
\]

以及估算 FLOPs、P50/P95 延迟、能耗或 GPU-seconds。自适应方法不能只报告平均 NFE，还需报告分位数和最坏预算。

### 6. 中间状态“当前得分”不等于可恢复轨迹的价值

搜索真正需要的是 \(\mathbb E[U(X)\mid z_t]\)，而目前 **3.3** 直接对不完整候选做语义/美学评分。一个早期模糊状态当前得分低但可恢复性高，另一个看似清晰的状态可能已经锁定错误结构。只按当前图像问答会系统性误剪枝。

建议把“验证器是否能预测最终回报”列为核心实验：从每个保存的 \(z_t\) 独立补全 \(L\) 次，以平均独立终局效用作为近似真值 \(\hat V(z_t)\)；按阶段报告自验证分数与 \(\hat V\) 的 Spearman/Kendall 相关、top-K recall、NDCG，以及“被剪候选中最终可进入 oracle top-K 的比例”。该误删率必须由额外补全得到，不能用已选中分支的最终结果估计。

搜索对照还应包括：

- 同 scheduler pool、同验证器、同总预算的均匀分配和随机剪枝；
- best-of-N 末端选择；
- 外部冻结验证器；
- 只用当前自评分与学习/校准后的 continuation-value 预测器；
- 使用独立测试指标选择的 oracle，仅作为上界，绝不能作为主结果。

达到“相近质量”的时延比较应预先规定目标点或报告完整 Pareto 前沿及其置信带，避免事后挑选有利交点。

### 7. 自反馈方案存在提示泄漏和移动奖励两项高风险

**3.4** 从提示生成问题和答案后，再让同一模型答题。若评价输入保留原始提示，模型无需看图即可回答；即使不保留提示，也可能利用问题先验。当前“理解分支使用图像条件答案似然”没有排除这一捷径。

建议精确写明：评价器只接收生成图像/视觉 token 与问题，不接收原始生成提示和标准答案；主要实验使用答案空间封闭、可程序核验的多项选择题，短答案仅作扩展；加入无图、图像遮挡、图像交换、问题反事实、提示—图像错配对照，并报告图像证据带来的增量准确率。问题生成器、答案构造规则和过滤器应在训练集上冻结，测试题模板或组合留出。

同步更新生成与评价分支会使奖励标尺随策略变化。建议把**冻结参考评价器或 EMA target evaluator**设为主奖励锚点；当前模型的评价仅作辅助或一致性项。若比较冻结、慢更新和同步更新，必须始终用同一个冻结审计集/评价器记录奖励漂移，不能用正在变化的评价器证明自身进步。

此外需要澄清训练图：生成图像或视觉 token 在形成奖励时 stop-gradient；理解损失与生成策略损失如何交替、是否共享同一 batch；提示生成的答案监督不得让理解分支通过文本泄漏学习。时间步抽样若不是均匀抽样，应使用相应重要性权重，或明确承认优化的是重加权时间步目标。

“生成—理解协同”需要预先设定理解非劣界 \(\delta\)，比较优化前后差值及 95% 置信区间；仅说“同时改善”过强，理解保持不退化同样是有效结论。

### 8. 粗到细蒸馏没有蒸馏“选哪些位置”，且硬目标方差高

**3.5** 只在 \(z_s\) 相对 \(z_t\) 新增可见位置计算交叉熵，但跨多步教师不仅决定 token 值，也决定哪些位置在何时揭示。若不监督新增位置集合/生成秩，学生可能学到 token 内容却学不到少步调度。

建议明确两类监督：

1. **位置/阶段监督**：蒸馏教师从 \(t\) 到 \(s\) 的新增掩码集合、生成秩或保留概率；若位置选择固定，则说明它是预设 schedule 而非学习结果。
2. **类别监督**：优先匹配教师在学生状态上的软分布（温度化 KL/交叉熵），硬采样 \(z_s\) 只作为 Monte Carlo 辅助。教师经过多步后的边缘分布通常无法由一次 logits 精确给出，使用单条硬轨迹是高方差估计，应对同一状态多轨迹平均或报告方差。

还存在“错误锁定”问题：教师从学生 \(z_t\) 继续补全时若固定所有已显式 token，学生早期错误无法纠正。应比较“严格冻结可见 token”与“对低置信可见 token 允许重掩码/纠错”两种方案，报告纠错率和结构错误累积。否则少步模型可能提高速度但把早期计数或布局错误永久固化。

总损失 \(L=\lambda_{RL}L_{RL}+\lambda_{KD}L_{KD}+\beta L_{KL}\) 还需定义每项是最小化损失还是最大化目标、KL 的方向和参考策略、各项按 token/样本怎样归一化。监测梯度夹角后再任选梯度投影、退火或分阶段训练容易被视为事后调参；应预先规定触发条件，并在独立验证集选择，不在测试集选择。

### 9. 结构价值的采样设计和多样性项定义不正确

**2.2（4）和 3.5** 写“以语义、质量和多样性奖励的加权平均作为结构价值”。多样性通常是样本集合属性，不能与每个样本奖励一起简单取平均。建议改为

\[
\hat V(z_\tau,c)=\frac1M\sum_{m=1}^{M}\bigl(w_s r_s(x_m,c)+w_qr_q(x_m)\bigr)
+w_dD(\{x_m\}_{m=1}^M),
\]

并明确 \(D\) 使用何种特征距离、是否排除语义偏离样本、权重只在开发集确定。为形成组内优势，同一提示至少需要 \(H\ge2\) 个结构候选，每个候选各完成 \(M\) 次；当前“同提示结构组”没有定义 \(H\)。建议报告 \(\hat V\) 的标准误或用置信下界筛选，防止均值差来自补全噪声。

计算量约为 \(H\times M\times\) 教师剩余步数，再叠加学生 rollout。报告没有给出 H、M、提示数和总 GPU-hours，这会直接引发可行性质疑。至少给出分阶段预算表：小模型/低分辨率机制验证、8B 单底座主实验、第二底座迁移验证，各阶段的 GPU 型号、数量、显存、预计训练时长和最大实验次数。参数高效训练只是手段，不等于已有资源足够。

### 10. 实验统计与成功标准仍不足以支撑“有效、稳定、加速”

“至少三个随机种子”应区分训练随机种子和同一 checkpoint 的采样随机种子。后者不能替代独立训练重复。建议：关键低成本消融做至少 3 次独立训练；大型主实验若受资源限制，至少对候选生成做成对 bootstrap，并对单次训练结论明确限定。所有方法使用相同提示和采样种子，以配对差值报告 95% CI。

第 **3.6** 建议补充：

- 预先固定 GenEval/DPG-Bench 的 prompt 数、每 prompt 图像数、评测代码版本和 checkpoint hash；测试集只运行最终配置。
- 多个类别/指标比较报告 bootstrap CI，并对主要假设预先指定主指标，避免只挑显著子项；必要时做多重比较校正。
- 人工评价预先规定样本数或功效分析、每对样本至少 3 名评价者、随机左右位置、允许平局、报告一致性和胜率 CI；记录利益冲突，作者不评自己的方法。
- 生成多样性单独报告，而不是只以偏好分数代替；可采用同提示多样性、重复率或基于独立视觉特征的成对距离，并同时约束语义正确性。
- 固定质量比较使用预先声明的非劣界；固定预算比较用完整质量—计算 Pareto 曲线。
- 预先定义“实际加速”和“理解不退化”的判定条件。例如令延迟下降比例及其 95% CI 超过预设阈值，理解差值 CI 的下界高于 \(-\delta\)。阈值应在实验前依据应用需求确定。

## 各研究内容应补齐的公平基线

| 研究内容 | 必需基线 | 必须匹配的预算 |
|---|---|---|
| 层次信用分配 | 基础/SFT、标准均匀 GRPO、随机重掩码、真实轨迹、随机 token 子集、熵排序但打乱生成秩、固定与动态分组 | rollout 数、奖励调用、反向 token 数、优化步数、训练 FLOPs、KL 目标 |
| 分层搜索 | 单轨迹、best-of-N、线性轨迹搜索、随机剪枝、相同 scorer 的均匀预算、外部冻结 verifier、oracle 上界 | 主模型轨迹步、验证 FLOPs、总 GPU-seconds、显存；同时给固定延迟和固定质量 |
| 自反馈 | 无 RL、外部奖励、冻结自评、EMA 自评、同步自评、混合反馈、图像交换/无图负对照 | 数据、rollout、更新步、奖励标度、KL、训练算力 |
| 少步蒸馏 | 原教师、教师直接少步、一步 Di[M]O 类、相同步数的普通蒸馏、纯结构 RL、先蒸馏后 RL、联合训练 | 教师调用、训练 FLOPs、学生步数、候选数、部署 batch 与硬件 |

其中“教师直接少步”非常重要：否则无法判断收益来自蒸馏，还是仅仅来自改变采样日程。“相同步数普通蒸馏”也必须有，才能证明结构价值而非蒸馏本身带来收益。

## 建议新增的核心实验表

建议在方案中承诺四张主表，能显著提高可审查性：

1. **代理比率有效性表**：分阶段报告真实轨迹比率与全掩码代理的相关、偏差、方差、显存、时间、最终质量。
2. **中间价值校准表**：各阶段自验证分数对多次终局补全价值的相关、top-K recall、误删率和校准误差。
3. **质量—计算 Pareto 表/图**：生成 NFE、验证 FLOPs、总 FLOPs、P50/P95 延迟、峰值显存、吞吐与质量同时列出。
4. **生成—理解安全表**：生成主指标、独立理解指标差值及 CI、无图/换图差值、奖励—人工相关、reward hacking 失败率。

## 容易被答辩委员追问的表述及建议替换

1. **原表述**：“HTS 使复杂度由 \(O(NT)\) 降为近似 \(O(N+T)\)。”
   **建议**：给出 \(N T_s+\sum_tW_t+K(T-T_r)\) 的实际代价，仅把 \(O(N+T)\) 说明为固定参数下简写。

2. **原表述**：“早期 token 往往决定对象数量、位置和大体布局。”
   **建议**：“现有实验提示早期生成阶段与全局结构相关，本课题将以干预敏感度和分层统计验证其成立范围。”目前的“决定”带有未证明因果含义。

3. **原表述**：“全掩码概率比估计。”
   **建议**：“全掩码提示条件代理比率。”除非动作确实在全掩码状态下采样，否则不应称真实重要性比率。

4. **原表述**：“Self-GRPO 后生成指标提升说明理解分支能够为生成提供有用语义反馈。”
   **建议**：“与理解分支构造的反馈能够改善所测生成指标相一致；反馈是否依赖真实图像证据，需由无图、换图和人工相关实验验证。”

5. **原表述**：“稳定增益。”
   **建议**：若原论文没有独立训练种子和置信区间，改为“在所报告底座与协议上均观察到增益”。跨模型同方向不等于统计稳定。

6. **原表述**：“模型自身理解能力评价候选。”
   **建议**：“模型理解头产生候选评分，并以独立人工/外部终局效用检验该评分是否能预测可恢复价值。”避免把自评分预先当成理解能力的可靠测量。

7. **原表述**：“多次补全用于降低一次随机补全的方差。”
   **建议**：“在独立同分布补全且奖励方差有限时，多次补全降低条件均值的 Monte Carlo 方差；同时报告有效样本数、标准误和额外教师成本。”

8. **原表述**：“至少两个底座验证跨模型可迁移性。”
   **建议**：“两个底座用于提供初步跨架构证据；结论限定于所测 tokenizer、规模和分辨率。”两个模型不足以证明一般可迁移性。

## 可行性方面的最低补充信息

正式版本应给出一张资源与降级路径表，至少包括：可用 GPU 型号/数量/单卡显存；8B、4096 视觉 token 在 rollout 和反向时的实测峰值显存；单个训练 step 与单次生成耗时；每项主实验预计 GPU-hours；最多允许的 H、M、G、N、T；是否全参训练或 LoRA；第二底座何时仅做迁移验证。若资源不足，预先说明先在较小底座或较低分辨率验证机制，再只对最佳配置扩展到 8B，而不是泛称“使用参数高效训练”。

还应明确第四项的停止/转向条件：若联合训练在预设预算内无法达到质量非劣界，则输出“条件补全价值估计与失败边界”，转为分阶段蒸馏；若 NFE 降低但端到端时延不降，则结论限定为算法步数压缩。当前报告已有类似态度，可进一步量化。

## 第一轮建议后的技术评价

报告的科学问题有价值，前三项工作为后续研究提供了可信起点。最需要处理的是三处逻辑错位：**代理比率被写成真实重要性比率、部分状态当前得分被当成终局条件价值、只蒸馏 token 值却没有蒸馏位置/日程**。修正这三点，再补上预算匹配、冻结奖励锚点、统计协议和具体算力表，方法链条才足以经受开题答辩中的技术追问。
