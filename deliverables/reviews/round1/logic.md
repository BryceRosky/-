# 第一轮审稿意见：研究逻辑、因果链与方案闭环

## 总体判断

**建议：大修后再审。** 选题具有博士论文所需的技术深度，前期成果也较扎实；当前稿件最大的优点，是已经主动区分 NFE 与真实时延、内部自评分与独立理解能力、阶段性结果与未完成方案，论断边界意识较强。但从严格开题委员视角看，全文目前更像“4 项相关工作的并列组合”，尚未完全证明它们构成一个不可替代的统一科学问题。核心术语“价值”在 token、状态、轨迹、问答分数、教师补全回报之间来回切换，四项内容的输入输出关系没有形式化；第（2）项自验证搜索和第（3）项自反馈训练共享评价器却被写成顺序递进，第（1）项结构强化学习和第（4）项结构策略强化又存在方法重叠。若不补上统一定义、依赖关系和可证伪标准，答辩委员很可能质疑“为何必须放在同一篇博士论文中”。

稿件主线可以成立，但应改写为：**先定义终局效用与中间状态条件价值，再分别研究价值信号是否可信、如何把价值分配到 token、如何据此分配在线计算、以及如何把高价值决策固化到少步学生。** 这样，Self-GRPO 是价值信号的校准与学习机制，HT-GRPO 是 token 级信用分配机制，TTS 是状态/轨迹级预算分配机制，粗到细蒸馏是离线能力迁移机制；四项工作才会形成闭环。

## Major concerns

### M1. “价值”是全文主线，但没有统一数学定义，导致四项工作只是语义上相似

涉及位置：第 9、57、65、91、107—111、121、127—131、139—143、237、259—265、293—295、329 行。

原句包括：

> “识别高价值生成决策、按价值配置训练与推理计算，并将搜索所得经验迁移为少步生成能力。”

> “四项研究共享同一价值概念，却分别作用于 token、轨迹、反馈和步数。”

问题在于，文中的“价值”至少指向五种不同对象：终局图像奖励、结构状态的期望补全回报、单个 token 的边际贡献、自验证问答分数、搜索分支优先级。这些量不天然相等。问答分数可以估计终局语义奖励，却未必是中间状态价值；早期 token 权重是启发式信用，不等于边际因果贡献；多次教师补全均值估计的是给定后续教师策略的状态价值，也不等于学生策略下的价值。如果不统一定义，所谓“同一价值视角”只是措辞统一。

建议在 2.1 后增加总体问题定义，例如：给定提示 `c`、离散去掩码轨迹 `τ=(z0,a0,…,zT)`、终局图像 `x` 和独立定义的多目标效用 `R(x,c)`，在计算约束 `C(τ)≤B` 与理解能力非劣约束下最大化 `E[R]`。定义 `Vπ(zt,c)=Eπ[R(x,c)|zt,c]`，token 边际贡献定义为对同一状态进行保留/重掩码干预后的价值差。随后明确：

- 第（3）项校准终局奖励 `R` 及其内部代理；
- 第（1）项估计 token 对 `V` 的边际贡献并进行信用分配；
- 第（2）项用 `V` 的估计值进行轨迹剪枝与预算分配；
- 第（4）项把高价值状态—动作及教师条件转移蒸馏到少步学生。

同时说明自验证分数只是 `R` 或 `V` 的代理，需由外部指标和人工判断校准，不能直接称为真实价值。

### M2. 四项研究的因果依赖没有闭合，第（2）与第（3）项顺序不自然，第（1）与第（4）项存在重复

涉及位置：第 139、143、237、241—255、271、293—297、317—329 行。

原句：

> “首先在训练侧……其次在推理侧……再次把生成与理解纳入结构化自反馈训练；最后……”

> “层次强化学习回答‘训练时更新哪些决策’，自验证搜索回答‘推理时继续计算哪些分支’，自反馈回答‘由谁判断结果价值’……”

“由谁判断价值”在逻辑上是第（1）和第（2）项的前提，不是搜索之后才出现的第三阶段。当前第（1）项用图像级优势却没有先说明优势由何种奖励产生；第（2）项用自验证分数，但可靠性研究被放在第（3）项；第（4）项又重新以组内优势训练“学生结构策略”，与第（1）项结构强化学习的关系不明。

建议不要硬写成时间顺序，而改成“一个基础信号、两个使用场景、一个迁移阶段”：第（3）项提供经校准的价值信号；第（1）项在训练端解决 token 信用；第（2）项在推理端解决轨迹预算；第（4）项接收第（1）项训练后的结构先验、第（2）项产生的候选轨迹和第（3）项校准后的评分，将它们迁移到少步学生。若学校模板必须保持四项编号，可保留编号，但需画出明确数据流并在每项结尾写“输出什么、供下一项如何使用”。

建议将第 139/143 行附近改为：

> 四项研究由共享的条件价值定义连接。自反馈模块负责构造并校准终局效用；层次信用分配利用该效用估计 token 的边际贡献；分层搜索利用同一价值代理决定轨迹扩展与停止；最后，少步学生以搜索得到的候选组、相对价值和条件转移为监督，将在线预算分配规律写入参数。前两类方法可独立验证，第四项通过交叉消融检验二者是否真正提供互补信息。

### M3. 科学假设、关键问题、研究内容和创新点数量不一致，缺少一一对应的验收结构

涉及位置：1.14 的三项假设（第 127—131 行）、2.2 的四项研究内容（第 241—255 行）、2.3 的四个问题（第 259—265 行）、第 4 章四个创新点。

三项假设中，第二项把“推理时自验证是否有效”与“训练时自反馈是否稳定”合并，但 2.3 又拆成两个关键问题。二者需要的证据不同：前者关注中间状态排序/误删率，后者关注奖励非平稳、理解退化和参数耦合。当前结构会使答辩委员无法判断每项创新由哪条假设支撑、用什么实验判定成立或否定。

建议采用四行闭环表，列出“科学假设—研究问题—方法—主要对照—成功/失败判据—对应创新”。可将第二项拆成 H2a（内部理解可排序中间轨迹）与 H2b（经稳定化的内部反馈可用于参数更新而不损害理解），形成四项假设；或者明确第（2）（3）项是同一假设的推理/训练两个子问题。正文必须选定一种结构并全篇一致。

### M4. “早生成 token 即结构 token”的表述前后摇摆，现有结果不足以支持因果结论

涉及位置：第 11、37—39、79、91、127、243、275—277、317 行。

原句一：

> “早期 token 往往决定对象数量、位置和大体布局，后期 token 更多补充颜色、纹理与局部细节。”

原句二：

> “token 的‘早/晚’并不必然等价于空间上的‘轮廓/纹理’……”

后文的边界意识是正确的，但开头和创新点仍把“早期=结构”近似当作已知事实。HT-GRPO 的性能提升只说明这套启发式在特定协议中有效，并不能单独证明早期 token 具有更大的因果贡献；三阶段、额外更新预算或熵变化本身都可能解释增益。

建议统一改成待检验假设：

> 初步实验表明，生成秩与结构性贡献在部分底座和提示类型上具有统计相关性；本课题不预设二者恒等，而将生成秩、熵、空间连通性和反事实价值差共同作为结构概率的候选特征。

验证应加入：（1）按对象分割区域/边界与背景评估生成秩分布；（2）保持其他条件不变，对 token 做保留、替换、重掩码干预；（3）用随机同预算权重、仅熵权重、仅生成秩权重作对照；（4）报告相关性与因果干预效应，而不只展示最终 GenEval。创新点 4.1 应由“利用实际去掩码顺序区分结构”改为“学习或估计结构概率，并检验生成次序能提供多少增量信息”。

### M5. 全掩码概率比是有偏代理，当前措辞容易给人“解决了策略概率估计”的错觉

涉及位置：第 37、89、243、275、317 行。

当行为动作由真实中间状态 `zt` 下的策略采样，却用 `πθ(ai|c,[M]^N)` 计算新旧概率比时，该比值不是行为轨迹的标准重要性比；“去除了未来泄漏”不意味着获得无偏策略梯度。稿件在综述中承认它是有偏代理，但研究内容和创新点又直接称“估计新旧策略概率比”，边界不够清楚。

建议全篇统一称“全掩码上下文下的代理比值/代理优化目标”，不要暗示其等于真实轨迹概率比。方法部分需写明：（1）代理优化的目标函数；（2）偏差来自去除历史条件和掩码选择事件；（3）与少量真实轨迹比值的相关性、裁剪率和梯度方向一致性如何测量；（4）若一致性不足，何时切换到部分上下文或混合估计。若无法给出理论误差界，应把贡献限定为“经实证校准的低成本 surrogate”，避免理论性过强的表述。

### M6. 自反馈训练存在潜在循环监督和奖励非平稳，当前方案缺少防止“评价器学会迎合答案”的关键机制

涉及位置：第 45—47、97—103、251、287—289、325 行。

原句：

> “理解分支使用图像条件答案似然……”

如果问题与“正确答案”直接从提示生成，而生成图像实际上没有满足提示，却仍用提示中的期望答案训练理解分支，则评价器会被训练为忽略图像、直接根据提示猜答案；之后它再给生成器打高分，构成循环确认。同步更新同一组共享参数还会使奖励函数随策略变化，标准 policy-gradient 推导中“奖励固定”的条件不成立。

需要明确以下机制：

1. 评分时对奖励路径 stop-gradient，并使用冻结或指数滑动平均的 target evaluator，而非刚更新的在线分支；
2. 理解损失只能使用有独立标签/外部校验的图文问答样本，不能把提示期望答案无条件当作生成图像事实；
3. 加入无图、错图交换、图像遮挡和反事实问题，测量模型是否真正依赖视觉证据；
4. 为冻结、慢更新、同步更新分别定义切换标准，主方案只能有一个，其余作为对照或故障回退；
5. 报告内部奖励与人工/外部奖励的秩相关、校准误差和随训练步数的漂移。

建议将“联合优化生成目标、理解目标”改写得更严格，例如：“生成策略由冻结目标评价器产生奖励；理解分支在独立、带标签的理解数据上更新，并以慢速同步更新目标评价器。提示派生问答仅用于评价生成是否满足条件，不直接作为错误生成图像的理解监督。”

### M7. 中间状态如何被视觉理解分支评价尚未定义，搜索复杂度 `O(N+T)` 的论断也不成立或至少条件缺失

涉及位置：第 51—55、97—99、247、281—283、321 行。

原句：

> “使搜索复杂度由线性笛卡尔组合的 O(NT) 降为近似 O(N+T)。”

一个部分去掩码的 token 序列未必能直接解码成可供 VQA 判断的自然图像。如果做临时补全，需计入补全 NFE；如果直接把 mask token 解码，验证器面对的是分布外输入；如果每个候选都继续若干步，主模型开销一般为 `N·Ts + K·(T−Ts)`，再加问题生成和验证调用，并非无条件的 `O(N+T)`。当前写法会被严格委员直接追问。

建议明确搜索节点的可观察形式：例如用一次确定性临时补全形成 probe image、用轻量 value head 读 token 状态，或只在能够稳定解码的阶段评价。给出精确成本式：`C = N·Ts + K·(T−Ts) + Cprobe + Cverify`，再说明在何种 `Ts、K` 设定下相对 `N·T` 节省。报告主模型 NFE、验证器等效 FLOPs 和墙钟时间三种口径。文献综述中将 `O(N+T)` 改为“在特定分层调度下显著减少候选—步数组合开销”，除非论文已有严格算法定义支持该大 O 结论。

### M8. “无需额外大型验证器”与实际方法中的外部质量/美学评分器相冲突

涉及位置：第 145、247、281、321 行。

第（2）项写“无需额外大模型验证器”，紧接着又写“加入与训练独立的质量/美学评分”；创新点仍声称“无需额外大型验证器”。如果这些评分器参与在线搜索，系统依然有额外模型及其时延/显存；如果只用于离线评价，则不应出现在筛选阶段；如果是可选的小模型，则应明确大小和成本。

建议选择并固定口径：主方法的语义排序只使用统一模型自身分支；质量/美学评分器若参与在线决策，就称“无需额外大型多模态语言验证器，但可选用轻量专用评分器”，并计入成本。外部验证器保留为上界/对照，不得同时被写成主方法的一部分和“无需外部验证器”的证据。

### M9. 第（4）项声称迁移“搜索经验”，但当前训练方案主要使用教师随机补全，没有明确消费第（2）项的搜索输出

涉及位置：第 57、65、107—111、121、255、293—297、329 行。

目前第（4）项从学生生成结构状态，再由教师随机补全；这能做 on-policy 条件蒸馏，却没有显式使用第（2）项保留/淘汰的轨迹、多调度器候选、误删信息或预算策略。因此“把在线搜索经验迁移到学生”在方法上尚未兑现。另一个不清楚之处是训练时学生“产生多个结构候选”，而推理时是否仍产生多个候选并筛选。如果仍需筛选，就没有完全去掉在线搜索成本；如果只采一条轨迹，应说明训练如何使单条策略吸收组内排序信息。

建议明确接口：第（2）项输出同提示候选组 `{zτ,g}`、校准价值、保留/淘汰标签、所用调度器和后续教师补全；第（4）项以候选组做排序/偏好蒸馏，以高价值状态做条件转移蒸馏，并用低价值候选学习决策边界。第（1）项训练所得结构分组器用于确定 `τ` 或初始化学生，避免重新发明结构 RL。推理阶段明确“每个提示仅一条学生轨迹、总步数 B”，若仍保留多候选模式，应分别报告单轨迹部署与增强模式。

### M10. 目标没有可证伪的主要终点，“提高质量与效率”无法形成开题验收标准

涉及位置：第 237、283、289、297、301—303、349 行。

当前列出了大量指标，但没有说明哪一个是主指标、什么结果算假设成立、什么结果算失败。例如“保证理解能力不退化”没有非劣界；“显著减少真实延迟”没有基准和置信区间；多指标同时尝试会提高择优汇报风险。

建议为每项内容预先指定一个主终点和若干安全/次要终点：

- 信用分配：固定训练算力下，独立语义指标相对强基线的均值提升及置信区间；同时多样性不得低于预设非劣界；
- 搜索：固定端到端时延下的质量，或固定质量下的真实时延；NFE 作为机制指标；
- 自反馈：内部奖励与人工/外部判断的秩相关，以及生成提升时理解基准的非劣性；
- 少步蒸馏：相同单轨迹部署条件下，在不超过预设质量损失时的真实加速，或固定时延下的质量提升。

不必在开题阶段承诺不现实的绝对数值，但应给出相对基线、统计检验、置信区间和失败判据。第 349 行“性能结论以实测为准”是必要边界，却不能替代验收标准。

### M11. 可行性分析缺少硬件、数据与阶段门，计划与四项内容也未完全对应

涉及位置：第 271、297、305—311、335—345 行。

可行性目前主要来自“已有工作有效”和“已有代码”，但模型为 8B、视觉序列长达 4096，G 条轨迹、M 次补全、两个底座、多个随机种子和四个理解基准叠加后，计算需求很高。没有 GPU 型号/数量、预计 GPU-hours、训练分辨率、样本规模、存储开销和降级方案，无法判断 2027 年 8 月前能否完成。计划从 2026 年末直接进入第（4）项，已完成的第（1）（2）项何时用统一协议重跑、与第（3）（4）项做交叉消融并不明确。

建议增加资源表和阶段门：小模型/低分辨率机制验证 → 单一 8B 底座完整实验 → 第二底座迁移验证；每阶段列数据量、候选数、预计 GPU-hours和停止条件。时间表中单列“统一复现 HT-GRPO/TTS/Self-GRPO 并建立共享价值接口”和“跨章节交叉消融”，避免到 2027 年 9 月才整理统一逻辑。参数高效训练可以是资源措施，但不能替代主方案所需的全量/共享参数效应验证。

### M12. 前期成果、拟扩展内容与博士论文创新之间的边界仍需更明确

涉及位置：第 39、53—55、317—329、353—363 行。

4.1—4.3 的基础方法已经对应 HT-GRPO、dMLLM-TTS、Self-GRPO，4.4 尚未完成；但“创新点”段落把已发表机制、开题后拟扩展机制和计划中的验证混在同一句中。委员可能追问：博士论文新增科学贡献是什么，是已有论文合集，还是有一个新的统一理论与联合方法？

建议每个创新点用三句话分别写：（1）已有基础及学生本人贡献；（2）现有不足；（3）本课题将新增的可验证内容。尤其要说明动态结构分组、置信度感知剪枝、评价器稳定化和搜索—蒸馏接口分别哪些已完成、哪些待完成。第 4.4 应标为拟解决的核心新增方法，其成功不应被前三项既有成果预先暗示。

## Minor concerns

1. **第 9 行因果语气过强。** “许多失败并非模型完全缺乏相关知识，而是……”缺少直接证据。建议改为“本课题提出并检验一种可能解释：部分失败来自有限计算和信用分配失配，而非仅由容量不足造成”。

2. **第 15 行对连续扩散的概括过度。** “固定多步求解”忽略不同求解器和可变步数方法；“理解任务通常需要另接……”也不宜作为离散模型优越性的普遍结论。改为“经典连续扩散系统通常依赖多次网络求值，统一理解常通过额外模块实现”。

3. **第 27、39 行把相关改进写成机制证据。** Self-GRPO 后 GenEval 提升只能说明整套方法有效，不能单独证明“理解分支提供了正确语义反馈”；HT-GRPO 的最终分数也不能证明早期结构信用是唯一原因。分别改为“与该解释一致”，并把机制证明留给消融、错图对照和因果干预。

4. **第 29、77 行把单个实现的 profiling 推广为一般瓶颈。** “不足以解决全部问题”“仍是系统成本的主要来源”应改为“在该实现中仍存在明显开销/是待测的重要来源”，随后用 profiling 验证。

5. **第 63 行从一个 Meissonic 设置推到一般蒸馏困难。** 虽有后续限定，仍建议把“说明”改为“在该设置中显示”，不要由单点实验推导普遍规律。

6. **第 73 行 TR-PTS 与本课题主线联系偏弱。** 参数选择经验不能直接证明生成 token 价值估计可行。建议只放在“研究能力积累”，不要作为方法论证据；MICE-Bench 也应作为可选外部泛化，不要进入主要验收闭环。

7. **第 83、301 行出现多参考编辑，形成范围外扩。** 标题和四项主内容均以文生图为核心。建议明确多参考编辑是“资源允许时的外部有效性测试”，不作为开题成功的必要条件。

8. **第 119 行“国内团队”分类应有明确机构依据。** 不宜仅按作者姓名或项目印象划分国内外；若无必要，可改为“国内外多个团队”。

9. **第 123 行“用户材料”不符合学术文体。** 改为“本课题前期材料”或直接写明对应论文/版本；版本差异应给出模型、分辨率和评测代码的已知差异，不能只写“合理原因可能是”。

10. **符号需统一。** `zt/zτ/zs`、`Ks/Kr`、`G/M/N/K/T/B` 应使用一致上下标并集中定义；时间方向（`s<t` 还是 `s>t` 表示更完整状态）也需明确。总损失中的 `LRL` 若本质是最大化目标，应说明符号约定。

11. **“多样性奖励的加权平均”定义含混。** 多样性通常是候选集合属性，不能直接与单样本语义/质量分数同样平均。应定义成组内距离、熵正则或覆盖率，并说明它进入状态价值还是单独约束。

12. **3.6 的“训练奖励解耦”需要具体化。** 若 ImageReward/HPS/DeQA 中任一项参与训练或搜索，它就不能同时作为独立主测试指标。建议预先划分训练评分器、模型选择指标和最终测试指标。

13. **理解“不退化”需匹配任务。** POPE、MMBench、SEED、MMMU 可测通用理解，但未必能直接测自评价可靠性；还应建立自身生成分布上的带人工标签验证集，测排序准确率、校准误差和错图敏感度。

14. **计划产出过于泛化。** “形成学术论文”应至少对应粗到细联合方案或统一评测协议的明确交付；否则无法看出后续两年工作的核心产物。

| 层级 | 待检验问题 | 核心方法 | 必要证据 | 失败判据 |
|---|---|---|---|---|
| 价值信号 | 内部理解是否真实依赖图像且可校准 | 冻结/慢更新目标评价器、反事实问答 | 与人工/外部判断相关；错图/无图性能显著下降；校准稳定 | 仅靠提示即可答对，或奖励随训练漂移失控 |

## 第一轮结论

当前稿件不存在显著的自相矛盾到无法成立的程度，且对多数风险已有文字承认；问题在于这些风险尚未被转化为可执行的主方案和可证伪的验收标准。完成上述修改后，论文主线可以从“若干相关方法的组合”提升为“围绕条件价值估计、分配与迁移的统一研究”。第二轮应重点检查：统一定义是否贯穿全文、四项内容是否真正共享数据与信号、主要终点是否可复验，以及所有已完成/拟完成结论是否保持清晰边界。
