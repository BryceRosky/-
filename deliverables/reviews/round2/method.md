# 第二轮方法与统计复核意见

## 复核结论

**结论：较第一轮有实质性改善，建议在完成以下少量关键修订后通过方法学复核。** 当前稿已补上统一状态—动作—价值框架，明确全掩码比率是 surrogate，开始完整核算搜索成本，将当前部分图像得分与条件补全价值区分，加入冻结评价器、泄漏对照、位置—类别联合蒸馏、主终点、非劣性、置信区间和三级资源包络。第一轮的主要原则性问题已经被正面处理。

剩余问题集中在“符号能否唯一对应一个可运行算法”和“阶段门是否有明确通过条件”。其中必须再改的四点是：行为策略快照与固定参考策略仍被混写；在线剪枝的置信区间没有样本来源；跨步类别软目标的条件上下文定义不成立；主终点与阶段门仍允许事后解释。其余问题可以用一两句话修正。

## 必须修改

### 1. 状态没有显式包含剩余预算与调度器，两个 B 和两个 D 发生符号冲突

位置：第 235—239、265、331 行。

当前 \(z_t\) 只表示 token 状态，但同一个 token 状态在剩余 4 步和剩余 20 步、不同 scheduler 下具有不同条件补全价值。公式 \(V^\pi(z_t,c)\) 与文字中的“剩余预算”不一致。另有三处符号冲突：\(D(z_T)\) 表示图像解码器，\(D\) 又表示多样性；第 239 行的 \(B\) 是总计算预算，第 265/331 行的 \(B=K_s+K_r\) 是采样步数。

最小修改建议：将第一段改为明确约定“\(z_0\) 为全掩码、\(z_T\) 为完整 token”，并定义扩展状态

\[
s_t=(z_t,M_t,t,b_t,h_t),
\]

其中 \(b_t\) 是剩余计算预算，\(h_t\) 是当前调度器；价值写为 \(V^\pi(s_t,c)\)。解码器改记 \(\operatorname{Dec}\)，多样性改记 \(D_{div}\)，总计算预算改为 \(B_{comp}\)，少步学生的步数预算改为 \(B_{step}=K_s+K_r\)。后文所有候选价值比较须限定在相同提示、阶段、剩余预算和 continuation policy 下。

### 2. 第 299 行把行为策略快照和固定 KL 参考策略混为 `p_ref`

裁剪比率若模仿 PPO/GRPO 更新，应以产生 rollout 的旧策略 \(\theta_{old}\) 为分母；固定参考模型 \(\theta_{ref}\) 用于 KL 锚定。二者可能相同于第一次更新，但在多次 inner-loop 更新后不是同一个对象。当前写

\[
\tilde r_i=p_\theta(y_i\mid c,[M]^N)/p_{ref}(y_i\mid c,[M]^N)
\]

会使实现者无法判断 ratio 和 KL 分别对谁计算。

最小修改建议：改为

\[
\tilde r_i(\theta)=\frac{p_\theta(y_i\mid c,[M]^N)}{p_{\theta_{old}}(y_i\mid c,[M]^N)},\qquad
L_{KL}=D_{KL}(p_\theta\|p_{\theta_{ref}}),
\]

并说明 \(\theta_{old}\) 在每批 rollout 后冻结、何时刷新，\(\theta_{ref}\) 在一轮实验内固定。若实际方法确实直接对固定参考策略做比率，则不要称为 PPO 式更新，并应把它作为另一 surrogate 单独定义。

### 3. 在线搜索中的“候选置信区间”没有可执行来源

位置：第 257、287、305、309 行。

第 305 行看起来每个候选只生成一个 probe image，但第 309 行依据“置信区间较宽”决定是否剪枝。一个 probe 分数本身不能产生候选级置信区间。离线价值审计虽对抽样状态补全 \(L\) 次，但不能在在线搜索时直接为新候选提供 CI。

最小修改建议：二选一并写清成本。

1. 在线为候选生成 \(P_t\) 个独立 probe completion，用均值和标准误形成区间；总成本加入 \(\sum_{t\in\mathcal E}W_tP_tL_p(t)\)。
2. 在线只生成一个 probe，由在独立校准集上拟合且冻结的 value/calibration model 输出 conformal 或 bootstrap predictive interval；报告区间覆盖率，并把训练与推理成本计入账本。

还需说明 probe 在候选状态的副本上完成，不把临时补全 token 写回活动轨迹；用于近似参考值的 continuation policy \(\pi_{cont}\) 在所有候选间固定。因此价值应写为 \(V^{\pi_{cont}}(s_t,c)\)，而不是未指明后续策略的“真实回报”。

第 307 行可补一个可复算公式：

\[
C_{gen}=NT_s+\sum_{t=T_s}^{T_r-1}W_t+K(T-T_r)
+\sum_{t\in\mathcal E}W_tP_tL_p(t),
\]

并另列问题生成、评价器和解码成本。这样“真实成本”才能从日志重建。

### 4. 第 327 行的跨步 token 软目标在数学上仍不明确

教师从 \(z_t\) 运行多步后，第 \(i\) 个位置被恢复时实际条件是某条教师路径中的 \(z_{u_i-1}^{(m)}\)，而不是初始学生状态 \(z_t\)。当前写“匹配 \(p_\phi(y_i\mid z_t,c)\)”无法表达教师从中间几步获得的新上下文；若直接在 \(z_t\) 上重新算 logits，又不是所称“教师跨步转移”。

最小修改建议：明确定义 Monte Carlo 投影目标。对同一学生状态运行 \(M\) 条教师路径，位置目标包含“在目标跨步窗口内被恢复的频率”和“目标新增位置数/掩码率”；类别目标写为

\[
q_{tok}(y_i\mid s_t,c)=\frac{1}{|\mathcal M_i|}
\sum_{m\in\mathcal M_i}p_\phi(y_i\mid z_{u_i^{(m)}-1}^{(m)},c),
\]

其中 \(\mathcal M_i\) 是该窗口内恢复位置 \(i\) 的教师路径集合。学生从 \(s_t\) 匹配这一投影分布。若计算上只保存教师硬 token，则明确其是该多步边缘的高方差 Monte Carlo 硬标签，并设置软目标/硬目标消融。位置分布还必须监督本步恢复 cardinality，否则仅有归一化的 \(q_\phi(i\mid s_t,c)\) 不能决定一次恢复多少位置。

### 5. 冻结评价器仍有反复查看最终基准造成调参泄漏的风险

位置：第 285、315—319、343 行。

第 317 行用 POPE、MMBench 和人工校验集决定评价器是否同步；第 343 行又把 POPE、MMBench 作为理解主终点。若训练期间反复依据这两个基准接受或拒绝 evaluator 更新，它们已成为验证集，不能再充当冻结主测试终点。“奖励路径 stop-gradient”只能阻止反向传播，不能解决这种数据层面的泄漏。

最小修改建议：设置三个互斥集合：自反馈训练集；用于同步/早停/校准的 validation-audit 集；只在最终配置锁定后运行一次的 final-audit 集。POPE、MMBench 若保留为主终点，不参与同步判断；同步门使用另行留出的理解/生成校准集。目标评价器必须是与在线生成策略物理分离的参数快照，在一个阶段内不会因共享主体参数更新而改变；EMA 只在阶段边界按预先规则更新。

人工或外部工具确认后用于理解训练的生成样本也必须与人工最终评价样本互斥。多项选择题需平衡正确选项位置并加入反事实干扰项，避免 evaluator 利用答案位置或模板先验。

### 6. 搜索记录与蒸馏记录之间存在审计指标泄漏和两套价值标签混用

位置：第 289、311、323—325 行。

第 311 行保存“内部与外部审计分数”，第 323 行又把搜索记录用于学生训练。如果 final-audit 或 oracle 分数进入学生标签，就破坏了“独立最终测试”。此外，\(\hat V_g\) 可能是搜索在线评价器给出的分数，第 325 行又用冻结教师的 \(M\) 次补全重新估计一个价值；两者对应不同 continuation policy，不能都称为同一 \(\hat V\)。

最小修改建议：将记录字段拆成 \(\hat V_{search}\)、\(\hat V_{teacher}\) 和 \(V_{audit}\)。学生只可使用训练划分中的 \(\hat V_{search}\) 或 \(\hat V_{teacher}\)；\(V_{audit}\) 与 oracle 标签加只读标志，只用于离线报告。排序主标签需预先指定：例如先用校准后的 \(\hat V_{teacher}\)，\(\hat V_{search}\) 只作辅助一致性损失；若二者排序冲突，按预先规则降权或丢弃，不能在测试后选择更有利者。候选组必须来自同一提示、同一阶段、同一剩余预算，并由同一冻结 continuation policy 估值。

## 统计与阶段门的最小补充

### 7. “一个主终点”与多个共同主终点相互矛盾，若不写判定式仍可事后解释

位置：第 247、335—347、421—427 行。

第 335 行称“一个预先指定主终点”，研究二和四却各有固定质量与固定预算两个主目标，研究三有生成与理解两个共同主终点。“Pareto 关系”本身也不是单一统计量。建议把措辞改为“每项研究指定一个主假设；主假设可由必须同时满足的共同终点构成”，并在门 A 输出一张填入数值的判定表。最小可执行判定如下：

- 内容一：相对同计算均匀信用，\(\Delta\)GenEval Overall 的 95% CI 下界大于 0。
- 内容二：在 validation 上冻结的质量目标 \(Q^*\) 处，相对线性搜索质量差 CI 下界大于 \(-\delta_G\)，同时端到端 GPU-seconds 或延迟差 CI 上界小于 0；完整 Pareto 曲线为支持性证据。
- 内容三：相对无自反馈同预算基线，\(\Delta\)GenEval 的 CI 下界大于 0，且 POPE、MMBench **分别**满足非劣性。不要对未经预先标准化的两个基准取宏平均后让一项提升掩盖另一项下降。
- 内容四：相对同一步数普通蒸馏，质量差 CI 下界大于 0；相对完整教师，质量差下界大于 \(-\delta_G\)，且单轨迹延迟差上界小于 0。三项均满足才支持“搜索知识带来少步实际加速”。

这些是建议的最小判定形式；具体 \(Q^*\)、\(\delta\)、硬件、batch size 和时间测量协议可以由 pilot 冻结，但正式测试前必须填成数值，不能仅写“具有可报告关系”或“稳定增量”。

### 8. 非劣界不应由测量方差直接决定

位置：第 239、347 行。

当前文字把重复测量波动、训练种子方差和人工可察觉差异都用于“确定非劣界”。统计方差决定需要多少样本和 CI 宽度，不应成为放宽可接受性能损失的主要依据；否则噪声越大，越容易设一个宽松的 \(\delta\)。

最小修改建议：改为“\(\delta\) 由科学或应用上可接受的最大损失确定，并以人工最小有意义差异和既有基线差距提供依据；pilot 方差只用于样本量、训练重复次数和可行性判断，不用于增大 \(\delta\)。” 若多个共同终点必须全部通过，可用 intersection-union 判定，不需要因终点数量放宽各自界值。

三次训练后，单纯对 prompt 做 bootstrap 仍不能概括训练随机性。建议对主结论使用“训练 run 为上层、prompt 为下层”的层次 bootstrap 或混合效应估计；若只有一次 8B 训练，则现有做法正确——只报告条件于该 checkpoint 的 prompt-level CI，并明确不能推断训练稳定性。

### 9. 阶段门仍使用不可证伪词语，门 P 的“至少一个终点通过”过弱

位置：第 361、405—413 行。

“代理量具有可报告的校准关系”“关键代理量通过预设校准检查”“至少一个预先指定生成主终点通过”都没有唯一判定。任何相关系数都“可报告”，四项研究中任意一项通过也不应自动允许所有模块进入迁移验证。

最小修改建议：

- 门 A 的交付物增加“数值化注册表”，为 proxy ratio 相关、value top-K recall、区间覆盖率、图像证据增量、最大 GPU-hours 和耐心窗口填入阈值与统计量。
- 门 M 按模块判定；只有通过自身校准阈值的模块进入主实验。例：搜索模块必须同时满足 value 排序优于随机且置信区间覆盖率达到冻结目标，自反馈模块必须满足真实图像相对无图/错图的增量下界为正。
- 门 P 改为“某模块的完整共同主终点通过，才允许该模块进入第二底座迁移”，不能由另一模块的成功代替。
- “代理梯度长期不一致”“梯度长期相反”“持续下降”等词都需在门 A 定义移动窗口、阈值和 patience；否则回退时点可被结果驱动。

## 资源可行性的剩余矛盾

### 10. 最低资源情形仍错误承诺“单底座证据”

位置：第 357—365、409、429 行。

第 357 行把小模型机制验证和大模型单底座主实验分为两级，但第 363 行又称“若只获得机制验证所需资源，则完成……单底座证据”。如果只有第一级资源，最多能承诺小模型或低分辨率证据，不能承诺第二级代表性大模型证据。第 429 行“主实验至少在一个代表性底座上完成”是预期目标，而非当前资源事实，应与资源阶段门对应。

最小修改建议：第 363 行改为“若只获得第一级资源，则完成机制级小模型/低分辨率证据，并将代表性大模型结论列为未验证；只有在门 M 前落实不少于 pilot 估算的主实验额度后才启动第二级。” 门 A 还应要求记录当前可实际调用的设备、配额来源和排队/中断约束；门 M 要求已有可执行配额覆盖冻结的主实验上限。这样既不虚构资源已获批，也能判断计划何时可执行。

建议补充一个资源公式或登记项：搜索 probe 的 \(P_tL_p(t)\)、价值审计的 \(L\) 次补全、蒸馏的 \(H\times M\) 教师路径、独立训练重复和人工评价分别占多少 GPU-hours/人时。当前第 359 行只明确了 \(H\times M\)，尚未把搜索在线 probe 和离线 value audit 完整列入预算上限。

## 次要但建议修正

1. 第 239 行把“人工评价共同界定的 \(R\)”用于一般价值定义，但训练和在线搜索无法实时获得人工分数。建议明确 \(R_{eval}\)、\(\hat R_{train}\) 与 \(\hat V\) 三层：人工只参与独立评估和校准，不暗示进入每次搜索。
2. 第 297 行的对象/边界区域统计若来自额外检测器或分割器，应注明只用于离线机制分析，或把其推理与训练成本计入；否则动态结构分组的部署输入不完整。
3. 第 325 行称 \(M\) 次补全“降低方差”时，可加一句由 pilot 的方差—成本曲线选择 \(M\)，并在门 A 冻结；不同候选必须用同样的 \(M\)，或使用序贯采样并计入自适应成本。
4. 第 339 行的 best-of-N 应明确用与主方法相同的冻结评价器选最终样本并计入末端评分成本；使用独立测试指标选优的 best-of-N 只能作为 oracle。
5. 第 349 行“至少三名评价者”可保留，但人工主终点应以评价样本为单位做 clustered bootstrap，并对同一评价者的重复判断建模；不要把每次点击当作独立样本。

## 第二轮总体评价

当前版本已经不再存在第一轮那种原则性混淆，技术主线也已具备可检验接口。完成以上最小修订后，状态—动作—价值、搜索—蒸馏和评价—资源三条链可以落实为唯一实验协议。若不修，最可能在答辩中被追问的是：`p_ref` 到底是谁、一个 probe 如何产生置信区间、教师多步后 logits 如何投影给一步学生，以及为什么四项中只要一个终点通过就能进入门 P。
